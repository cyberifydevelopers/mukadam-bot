Muccaddam Bot - how it works, start to finish

Gmail mail comes in, the bot reads the PDF, asks the approver on WhatsApp, and saves to the dashboard. Every signed-in person has their own copy of all of this.

1. Signing in (each person gets their own dashboard)

Open the dashboardNot signed in → sent to /login
"Continue with Google"/auth/google/start → Google asks for permission to read Gmail (offline, so a refresh token is given)
Callback /auth/google/callbackChecks the permission was ticked, gets the Gmail address, checks ALLOWED_EMAILS (if set)
User created, own folder madedata/tenants/<id>/: own database, PDFs, reports, formats, WhatsApp number. User 1 keeps the original data.
Gmail watch started for that mailboxSigned cookie set (30 days) → dashboard opens showing only this person's data

2. A new mail arrives (target: a few seconds)

Bank / supplier emails a PDF to the Gmail account
Gmail → Google Cloud Pub/Sub topic"Google notified" time. This part is Google's and cannot be shortened.
POST /webhook/gmail?token=… on RailwayChecks PUBSUB_VERIFICATION_TOKEN, answers OK at once, then syncs on a background thread
Sync for every userOne Pub/Sub topic serves all mailboxes. Each user: Gmail History API from their saved cursor → new messages → download PDF attachments → "picked up" time
FallbacksSafety check every few minutes · Gmail watch renewed automatically before it expires (about 7 days) · "Check Gmail now" button

3. Reading the document

PDF saved in the user's folder
AI reads itType of document, bank, reference, date, amount, currency, items table, enclosed documents
Account statementSkipped - not tracked
Could not readMarked failed; "Re-parse" on the dashboard
Invoice / bank documentContinues below
Safety checksReally sent by that bank? (bank address in the email) · addressed to us? · amount in USD? → flagged in the prompt
Status: waiting for confirmation

4. WhatsApp approval

Prompt sent through OpenWA to the user's approver numberDetails, checks, USD alert, items, "View file" link. Long text is split: "(#16 continued, 2/2)". The last part is the one the answer is matched to.
Approver replies
OpenWA → /webhook/openwaSignature checked → which user owns the sender's number → that user's database
YES / YES 16 / 👍Saved. Dashboard turns Confirmed. Sheet written only if one is set up (a Sheet error no longer blocks the save).
NO / 👎Skipped, not saved
"pkr amount 1500000"USD document: rupee amount kept, report made in rupees
"rate wheat 3800", "margin 5"Figures for a stock report; report made again
"share pdf for 16"Sends the report PDF + Excel (or "original pdf 16")
Any questionAnswered by AI from the reports

5. After YES on a delivery order

Stock report builtFrom the saved Excel format for that bank + customer, stock profile figures, USD→PKR if known
PDF + Excel sent back on WhatsAppCaption lists anything still missing (rate, margin, weight…) and the dashboard shows an alert until given

6. Dashboard

Browser polls /activity/version every 2 secondsCheap check against the server's own database; only when something changed does it reload the lists, and plays the soft chime. Mail never waits on this: it is processed on the server the moment it arrives.
